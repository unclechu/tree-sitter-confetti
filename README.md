# Tree-sitter Confetti grammar

A generic [Tree-sitter](https://tree-sitter.github.io/tree-sitter/) grammar for
[Confetti 1.0](https://confetti.hgs3.me/specification/).

- Plain C parser and scanner.
- No C++ bindings or C++ compiler are required.
- Node.js **is not required** to compile or use the grammar,
  as the generated C sources are already included.

## Grammar generation

The [grammar definition](grammar.js) is written using Tree-sitter’s JavaScript
DSL, which is the conventional way of describing Tree-sitter grammars.

The actual parser is generated in C using the `tree-sitter generate` command.
The external scanner is handwritten in C.

By default, Tree-sitter uses Node.js to evaluate `grammar.js` and produce a
[JSON representation](src/grammar.json) of the grammar. The parser generator
itself is written in Rust and generates C code from this representation.

Since version 0.26, the Tree-sitter CLI also supports an experimental built-in
QuickJS runtime. It allows the parser to be generated from `grammar.js` without
requiring Node.js:

```sh
tree-sitter generate --abi 14 --js-runtime native
```

Alternatively, the C parser can be regenerated directly from the
[generated JSON grammar](src/grammar.json), without executing JavaScript:

```sh
tree-sitter generate --abi 14 src/grammar.json
```

Both commands generate a parser targeting Tree-sitter ABI 14 for compatibility
with older Tree-sitter runtimes.

Neither grammar generation nor a JavaScript runtime is necessary to compile
the already-generated C sources included in this repository.

## Supported syntax

The grammar implements the core Confetti 1.0 syntax:

- Directives with untyped arguments, including directives without additional
  arguments.
- Nested `{ … }` subdirective blocks, including empty blocks.
- Newline and semicolon directive separators, including adjacent directives
  following a closing `}` without an explicit separator.
- `#` comments.
- Plain arguments and escaped reserved punctuation, such as `foo\#bar`.
- Double-quoted strings, triple-quoted multiline strings, and escaped
  characters.
- Backslash–newline continuations in directives and ordinary quoted strings.

The resulting concrete syntax tree (CST) distinguishes directive names,
subsequent arguments, and subdirective blocks.

The grammar does **not** assign meaning to `if`, `+`, `id`, or any other
application-specific word. The optional Confetti expression-argument,
C-style comment, and punctuator extensions are **not** included; this grammar
tracks the core language without choosing extensions on an application's
behalf.

### Syntax highlighting

The [`queries/highlights.scm`](queries/highlights.scm) file provides generic
Tree-sitter highlighting rules for:

- **Directive names** — Highlighted as functions when they resemble identifiers,
  including names containing underscores and hyphens, such as `foo-bar` and
  `some_function`.

- **Strings** — Ordinary double-quoted strings and triple-quoted multiline
  strings.

- **Comments** — Lines and trailing comments beginning with `#`.

- **Numbers** — Numeric-looking arguments, including:
  - Integers: `42`, `-3`, `1_000`.
  - Floating-point numbers: `3.14`, `.125`, `-1.5`, `1_234.5`.
  - Exponential notation: `1e-3`, `2.5e+10`.
  - Numeric values with suffixes: `3s`, `4000k`, `1920x1080`.
  - Version-like values: `1.2.3`.

- **Operators** — Arithmetic (`+`, `-`, `*`, `/`), comparison (`==`, `!=`,
  `<`, `>`, `<=`, `>=`), and logical (`&&`, `||`) operators.

- **Punctuation** — Curly braces `{` and `}`, and semicolon separators `;`.

Numbers and operators are **not** special tokens in the Confetti grammar.
They are parsed as ordinary untyped arguments and classified for highlighting
based on their textual representation.

Consequently, numeric highlighting does not imply numeric validation, and
operator highlighting does not imply expression evaluation or precedence rules.

Directive names are highlighted as functions only when they match the
identifier-like pattern. For example, `foo-bar` is highlighted as a function
name, while `init.c` is treated as an ordinary argument.

The highlighting queries are application-independent and can be used by
Tree-sitter integrations such as Neovim. The actual colors depend on the
editor's highlighting configuration.

### Example

```confetti
# Project configuration
project "demo" {
  version 1.2.3
  sources { init.c fork.c scheduler.c }

  timeout 3s
  resolution 1920x1080
  retries 1_000

  calculate 2 + 3
  enabled true

  message """Hello,
Confetti!"""
}

step configure; step run
```

This example illustrates parsing and highlighting only. The grammar does not
define the behavior of the directives or operators.

## Build the native C parser

With a C11 compiler and `make`:

```sh
make
```

This builds `build/libtree-sitter-confetti.so` from `src/parser.c` and
`src/scanner.c` using `cc`. The repository ships the generated C files, so
**building the parser does not require Node.js, a C++ compiler, or the
Tree-sitter CLI**.

When embedding it in a C program, use the official `libtree-sitter` C runtime
and call `tree_sitter_confetti()` to obtain the language description:

```c
#include <tree_sitter/api.h>
#include "bindings/c/tree_sitter_confetti.h"

TSParser *parser = ts_parser_new();
ts_parser_set_language(parser, tree_sitter_confetti());
```

The complete [C embedding example](examples/embed.c) can be built on systems
with `libtree-sitter` installed, for example:

```sh
CFLAGS=$(pkg-config --cflags --libs tree-sitter)
cc -std=c11 -Isrc examples/embed.c src/parser.c src/scanner.c $CFLAGS -o confetti-parse-demo
./confetti-parse-demo
```

## Using [Nix](https://nixos.org)

You can enter a `nix-shell` first and all the necessary dependencies for
building the grammar will be provided:

```console
$ nix-shell
$ make
mkdir -p build
gcc -O2 -std=c11 -fPIC -Wall -Wextra -Wpedantic -Isrc -shared src/parser.c src/scanner.c -o build/libtree-sitter-confetti.so
```

Or:

```console

$ tree-sitter test
```

Or build the grammar derivation constructed by
`nixpkgs.tree-sitter.buildGrammar` helper:

```sh
nix-build -A tree-sitter-confetti-grammar
```

## Develop and test the grammar

Install the [Tree-sitter CLI](https://tree-sitter.github.io/tree-sitter/cli/)
when you want to edit `grammar.js` or run the corpus tests:

```sh
tree-sitter generate --abi 14
tree-sitter test
tree-sitter parse test/samples/core.confetti
tree-sitter query queries/highlights.scm test/samples/core.confetti
```

The generated parser targets ABI 14 for compatibility with runtimes that
support that ABI. `src/grammar.json` also lets you regenerate without a JS
runtime:

```sh
tree-sitter generate --abi 14 src/grammar.json
```

Tests cover simple and nested directives, adjacent directives, quoted and
multiline strings, escaped punctuators, comments, and continuations. Confetti
itself remains the authority on language conformance.

### Neovim

For non-Nix environment Tree-sitter grammar configuration see:
https://neovim.io/doc/user/treesitter/

Here is a simple example for making a Neovim configuration with this grammar
included using [Nix](https://nixos.org/).

Create `neovim-with-tree-sitter-confetti.nix`:

```nix
{ pkgs ? import <nixpkgs> {} }:

let
  tree-sitter-confetti-source = pkgs.fetchFromGitHub {
    owner = "unclechu";
    repo = "tree-sitter-confetti";
    # Pick the top `master` branch commit hash of
    # https://github.com/unclechu/tree-sitter-confetti
    rev = "ffffffffffffffffffffffffffffffffffffffff";
    # Try to build it first and put the actual hash here
    # taken from the build error message.
    #
    # For example:
    #  error: hash mismatch in fixed-output derivation '/nix/store/8im02sqwjrsqi3zhfas4c5q9vpw9yf0w-source.drv':
    #    specified: sha256-AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=
    #       got:    sha256-qSBFy8V9Pnk86MQEIEvKpi/o/7arYDpVnWN6frFEMAA=
    #
    # Then you replace `pkgs.lib.fakeHash` here with
    # `"sha256-qSBFy8V9Pnk86MQEIEvKpi/o/7arYDpVnWN6frFEMAA="`
    # and run the `nix-build neovim-with-tree-sitter-confetti.nix` again.
    hash = pkgs.lib.fakeHash;
  };

  tree-sitter-confetti = pkgs.callPackage tree-sitter-confetti-source {};
in

pkgs.neovim.override {
  configure = {
    packages.treesitter.start = [
      (pkgs.vimPlugins.nvim-treesitter.withPlugins (grammars: [
        tree-sitter-confetti.tree-sitter-confetti-grammar
      ]))
    ];

    customRC = ''
      lua << EOF

      -- Recognize `*.confetti` files.
      vim.filetype.add({ extension = { confetti = "confetti" } })

      -- Create the autocommand group, clearing previous registrations.
      local group = vim.api.nvim_create_augroup(
        "confetti_filetype_configuration",
        { clear = true }
      )

      -- Configure Confetti buffers.
      vim.api.nvim_create_autocmd("FileType", {
        group = group,
        pattern = "confetti",
        callback = function(ev)
          -- Enable Confetti hash-sign comments.
          vim.opt_local.commentstring = "# %s"
          vim.opt_local.comments = "b:#"

          -- Make dashes part of words.
          vim.opt_local.iskeyword:append("-")

          -- Enable Tree-sitter highlighting for this buffer.
          vim.treesitter.start(ev.buf)
        end,
      })

      EOF
    '';
  };
}
```

Then run:

```sh
nix-build neovim-with-tree-sitter-confetti.nix
echo 'foo { bar baz 123s + 456 }' > example.confetti
result/bin/nvim example.confetti
```

Note that default Neovim colorscheme might not give you all the useful
highlights. For example numerics and block braces might look neutral.
Try `:colorscheme zaibatsu` for example, it’ll give you more highlights.

This example included to [`default.nix`](default.nix).
So you can just run while being inside of this repository clone directory:

```sh
nix-build --arg useNixpkgsPin true -A neovim-example -o result-neovim-example
result-neovim-example/bin/nvim test/samples/core.confetti
```

Adding Tree-sitter grammar by itself won’t set up automatic file type detection.
You might want to add this to your Neovim config:

```vim
augroup confetti_filetype_configuration
  autocmd!
  " Set confetti file type for *.confetti files.
  autocmd BufNewFile,BufRead *.confetti setfiletype confetti
  " Enable Confetti hash-sign comments.
  " iskeyword+=45 for making dash be part of a single word
  " (e.g. foo-bar-baz will be recognized as a single word instead of 3 words).
  autocmd FileType confetti setlocal commentstring=#\ %s comments=b:# iskeyword+=45
augroup END
```

Or using Lua API:

```lua
-- Recognize `*.confetti` files.
vim.filetype.add({ extension = { confetti = "confetti" } })

-- Create the autocommand group, clearing previous registrations.
local group = vim.api.nvim_create_augroup(
  "confetti_filetype_configuration",
  { clear = true }
)

-- Configure Confetti buffers.
vim.api.nvim_create_autocmd("FileType", {
  group = group,
  pattern = "confetti",
  callback = function()
    -- Enable Confetti hash-sign comments.
    vim.opt_local.commentstring = "# %s"
    vim.opt_local.comments = "b:#"

    -- Make dashes part of words.
    -- For example, foo-bar-baz is recognized as one word.
    vim.opt_local.iskeyword:append("-")
  end,
})
```
